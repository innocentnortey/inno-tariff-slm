An AI trade-compliance analyst that knows when to ask.

Importers have to put a 10-digit tariff code on every product they bring into the US. We propose a human-supervised analyst that reads the product, finds the plausible codes, and uses a small fine-tuned model to choose between near-identical codes, or to ask the one question that decides it.

01 The business problem

One product, thousands of look-alike codes, and real money on each digit.

Every imported product needs a Harmonized Tariff Schedule (HTS) code. The first six digits are international. The last four are US-specific and turn on details such as fiber content, knit or woven, who the garment is for, or what the shoe's upper is made of. The importer is legally responsible for getting it right.

Same product family, same chapter. The only difference is whether silk is at least 70% of the weight. CBP ruling NY N346508 (March 2025) placed a 100% woven silk scarf in the 1.2% line.

Before shipping, importers also check Chapter 99 additional duties, which depend on country of origin.

It's slow

Classifiers read the product spec, the schedule's nested headings, the chapter notes and past CBP rulings before they commit to one line.

It's risky

A wrong code means a wrong duty: overpaying, or underpaying and facing penalties. Errors repeat across every shipment of that product.

It's hard for general AI

In ATLAS (2025), GPT-5-Thinking got 25.0% of 10-digit codes fully right and Gemini 2.5 Pro Thinking got 13.5%. At 6 digits, GPT-5-Thinking reached 55.5%. Established

02 Product vision

An autonomous, human-supervised trade-compliance analyst.

The analyst does the reading, lookup and arithmetic a classifier does today. It recommends a code with evidence, asks the supplier when a fact is missing, and sends risky decisions to a licensed person. It never files a legally binding determination on its own. Proposed

1

Ingest anything the importer has

Product descriptions, supplier invoices, catalogs and spec sheets.

2

Extract the attributes that matter

Materials and fiber percentages, knit or woven, construction, intended user and use, value.

3

Retrieve plausible codes and precedents

Schedule lines, chapter notes and similar CBP rulings.

4

Decide between close codes

The fine-tuned specialist chooses the code and names the attribute that rules out the runner-up.

5

Ask instead of guessing

When the deciding fact is missing, it drafts one targeted question for the supplier.

6

Compute duty scenarios

Deterministic code applies validated rates, country-of-origin duties and landed cost.

7

Explain with evidence

Every recommendation cites the schedule text, the deciding attribute and the precedent ruling, with an audit trail.

8

Escalate to a human

Low-confidence, high-duty or conflicting cases go to a licensed customs broker for sign-off.

What sets it apart is the whole operational workflow, from intake to a reviewed, documented decision. A code generator alone isn't the product.

04 Business value

Why an importer or broker would pay for it.

The buyers are mid-size importers, customs brokers and cross-border e-commerce sellers who classify hundreds to thousands of products a year. We haven't measured any savings yet. The value claims are the hypotheses the product has to prove with pilot customers. Hypothesis

Less manual research

The analyst assembles candidates, schedule text and precedents, so a reviewer checks a recommendation instead of starting from a blank search.

Fewer preventable errors

It asks for a missing attribute instead of guessing, which targets the error a busy person makes most.

Cost visibility before shipping

Duty and landed-cost scenarios show what a classification costs, including origin-based additional duties.

Defensible records

Each decision keeps its evidence, version and reviewer, which supports audits and CBP inquiries.

05 Why a trained small model

We train one narrow behavior, not the whole analyst.

Retrieval finds the plausible codes. Deterministic code does the arithmetic. The model we fine-tune does one job: choose between close candidates using the product's attributes, and recognize when it can't.

Behavior spec Proposed

Given a product description and eight candidate HTS codes with their schedule text, the model returns one JSON object that either selects exactly one candidate and names the deciding attribute in words taken from the description, or returns NEED_INFO naming the attribute whose absence keeps it from choosing. It never selects a code when the description lacks that attribute, and it never cites an attribute the description doesn't state.

Pass

{"decision": "SELECT",
 "code": "6114.30.30.70",
 "deciding_attribute": {"dimension": "gender_age",
                        "value": "Woman's"},
 "runner_up": "6114.30.30.60"}

Correct code (CBP ruling NY N344447), and the attribute is quoted from the description.

Fail: false confidence

{"decision": "SELECT",
 "code": "6404.19.39.40",
 "deciding_attribute": {"dimension": "gender_age",
                        "value": "men's"},
 "runner_up": "6404.19.39.60"}

The shoe's description never says who it's for, so citing "men's" is unsupported. The right answer is NEED_INFO.

Cost

A catalog has thousands of lines, and each one is re-checked when rates or products change. A 1.7B–4B model costs a fraction of a frontier call per item.

Latency

A short structured answer from a small local model fits an interactive review screen.

Privacy

Unreleased product specs and supplier pricing can stay on the importer's or broker's infrastructure.

Consistency

The same input gives the same output, a fixed schema and a pinned version, which helps audits.

06 Training data

Real customs decisions as ground truth.

CBP publishes its binding rulings: an importer describes a product, and CBP states the code with its reasoning. That gives us thousands of real input-to-decision examples, labelled by the agency itself rather than by a model.

Why we start narrow: apparel and footwear

We profiled the rulings by chapter. Chapters 61 (knit apparel), 62 (woven apparel) and 64 (footwear) have the most rulings with currently valid codes. Their codes split on attributes you can name and check: fiber content, knit or woven, gender, and the material of the upper. Footwear averages about 42 sibling 10-digit codes under each 6-digit subheading.

How each training example is built Proposed

FilterOne 10-digit code, still valid in today's schedule, in the chosen chapters.
Split by dateTrain on older rulings, test on 2024–2025 rulings, so the test postdates most model training data.
Hard negativesSeven nearest siblings from the schedule tree become the candidate list.
Deciding attributeRead from where the gold code's schedule path and its nearest sibling's path first differ.
Ask-when-unsure casesEither the attribute is missing from the summary, or it's removed on purpose. Both are labelled NEED_INFO.
ExplanationsA teacher model writes short rationales that are kept only if they agree with the ruling. Labels never come from the teacher.

From the simplest credible system to production

Version 1: concept to demo Proposed

  • Apparel and footwear only; candidates from the schedule tree
  • One specialist call per product; general duty rate only
  • Every recommendation goes to a reviewer queue
  • Evidence: schedule path, deciding attribute, nearest CBP ruling

Production challenges to design for Future

  • Effective dates: the schedule changes during the year; classify against the version in force on the entry date
  • Origin-based duties: Chapter 99 measures (for example the China note cited in NY N344447), exclusions and trade remedies
  • Old or conflicting rulings: 3,154 subset rulings cite codes that no longer exist
  • Accountability: risk tiers decide which recommendations a licensed broker must sign
  • Retrieval quality: plain keyword search put the right code in the top 8 for only 4% of test rulings, so retrieval needs its own design
08 Evaluation strategy

How we'll prove fine-tuning helps, or find out that it doesn't.

We build the evaluation before any training. Every model gets the same eight candidates, so a wrong answer is a decision error, never a retrieval miss. We measure retrieval recall separately.

Step 2 · Baselines on the same candidates

Step 3 · Data-efficiency curve Not yet run

Four QLoRA checkpoints on nested subsets (for example 500, 1,000, 2,000 and 4,000 rulings), all scored on the same held-out set. We report the smallest N that clears the bar.
